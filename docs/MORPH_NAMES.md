# What a morph is called in each naming mode

Generated by `Tools/morph_name_table.py` from four exports of the same model, one per
`Config.PmxMorphNameMode`, then checked against those files: every name below is really in the
corresponding `.pmx`. Mode 2 (`Both`) writes the tagged name and the short name for every morph,
so it is the union of the two columns.

A vmd morph name field holds 15 shift-jis bytes. Names longer than that cannot be used by a
motion, which is why mode 0 is model-only.

In this model (character 1001, costume 00): mode 0 writes **240** morph entries -
the same morph baked onto two meshes, e.g. `M_Face` and `M_Mayu`, stays two entries there -
modes 1 and 3 write **192** and **192** because those spellings merge them,
and mode 2 writes **432**. Every morph here has a usable tag, so no unified name falls
back to the short spelling; a morph without one (or whose unified name would not fit) keeps its
short name instead, which is the only case where the two columns are identical.

Regenerate with:

```powershell
./Tools/morph_name_table.py --tagged "fork_fixed_1001_00.pmx" --short "1001_Special Week_ag.pmx" --both "fork_both_1001_00.pmx" --unified "unified_1001_00.pmx" --out docs/MORPH_NAMES.md
```
